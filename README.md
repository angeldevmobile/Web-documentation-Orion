# Orion website and documentation

The website of the [Orion programming language](https://github.com/angeldevmobile/Orion):
the landing page, the documentation, the module reference and the browser
playground.

Built with Vite, React, TypeScript, Tailwind CSS and shadcn/ui. The
documentation is written in MDX, and code is highlighted at build time with
[Shiki](https://shiki.style) using the same grammar as the VS Code extension.

## Running it locally

Requirements: Node.js 18 or newer.

```bash
npm install
npm run dev        # http://localhost:8080
```

| Command | What it does |
|---|---|
| `npm run dev` | Development server with hot reload |
| `npm run build` | Production build in `dist/` |
| `npm run preview` | Serves the production build |
| `npm run lint` | ESLint |

The playground talks to a separate API
([PlayGround---API](https://github.com/angeldevmobile/PlayGround---API)). Point the
site at it with `VITE_PLAYGROUND_API_URL` in a `.env` file; without it, the
playground uses `http://localhost:3001`.


## Writing documentation

Each page is a file in `src/content/docs/<section>/<page>.mdx`, served at
`/docs/<section>/<page>`. The sidebar and the previous/next links are built
from these files, so adding a page is just adding a file:

````mdx
---
title: "Error Handling"
description: "Recover from errors with attempt and handle."
order: 5
---

Wrap code that may fail in an `attempt` block.

```orion
attempt {
  result = 10 / 0
} handle err {
  show err
}
```

<Note type="tip">
`<Note>` takes `type="note"`, `"tip"` or `"warning"` and needs no import.
</Note>
````

- `title` and `description` appear at the top of the page; `order` sets its
  position within the section.
- Code fences tagged `orion` are highlighted with the Orion grammar; `bash`,
  `powershell`, `json`, `toml`, `rust` and `python` work too.
- Links that start with `/` stay inside the site.
- New sections are declared in `SECTIONS`, in `src/content/docs/index.ts`.

Every Orion example should compile with the current release: run it with
`orion file.orx` (or at least `orion --check file.orx`) before publishing.

## Keeping it in sync with the language

- **Version and module count:** `src/lib/site.ts`. Update `ORION_VERSION` on
  each release.
- **Module reference:** `src/data/builtins.json` comes from the compiler. In the
  [Orion repository](https://github.com/angeldevmobile/Orion), run
  `orion --builtins-json` and copy the result here.
- **Syntax highlighting:** if the grammar in the VS Code extension changes, copy
  `syntaxes/orion.tmLanguage.json` to `src/content/orion.tmLanguage.json`.
- **Benchmark figures** on the landing page (`src/components/home/Performance.tsx`)
  come from `bench/` in the Orion repository.

## Deployment

The site is deployed on [Render](https://render.com) as a static site, using
`render.yaml`: `npm ci && npm run build`, publishing `dist/`, with every route
rewritten to `index.html` so links like `/docs/language/shapes` work when opened
directly. Pushing to `master` redeploys it.
